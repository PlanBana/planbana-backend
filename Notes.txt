## Steps to Run the Project


mvn spring-boot:run 👈👈👈👈 command to run backend 

1. __Prerequisites already satisfied on this machine:__

   - Java 21.0.8 ✅
   - Maven 3.9.4 ✅

2. __Database__ — you have two options: 👈👈👈👈

   - __Use the existing Atlas cloud MongoDB__ (already configured in `.env` via `MONGODB_URI`) — no extra setup needed, just ensure internet access and that the Atlas cluster allows your IP.
   - OR __run MongoDB locally__ with Docker (`docker-compose up -d mongo mongo-express`) if you install Docker Desktop, then uncomment the local `MONGODB_URI=mongodb://localhost:27017/planbana` line in `.env` and comment out the Atlas one.

3. __Redis__ (optional but recommended since a `RedisTemplate` bean exists): install/run Redis locally on port 6379, e.g. via Docker: `docker run -d -p 6379:6379 redis`. The app will still boot without it, but any code path using Redis will throw connection errors at runtime.

4. __Verify `.env`__ in project root — it already contains `MONGODB_URI`, `JWT_SECRET`, `GOOGLE_CLIENT_ID/SECRET`, mail and admin settings. Adjust `MAIL_HOST`/`MAIL_PORT` if you want real email delivery (currently points to `localhost:1025`, a MailHog/Mailtrap-style dev SMTP catcher — you can run one via Docker: `docker run -d -p 1025:1025 -p 8025:8025 mailhog/mailhog` if you want to see verification emails).

5. __Run the application__ from the project root:

   ```powershell
   cd "e:\Planbana Workspace\planbana-backend"
   mvn spring-boot:run 👈👈👈👈
   ```

   or build a jar and run it:

   ```powershell
   mvn clean package -DskipTests
   java -jar target/backend-0.1.0.jar
   ```

6. __Access the app:__

   - API base: `http://localhost:8085`
   - Swagger UI: `http://localhost:8085/swagger-ui/index.html`
   - Actuator health: `http://localhost:8085/actuator/health`

7. __Note on Mongock migrations__: this project uses Mongock for DB migrations, so on first run it will attempt to apply migrations against whichever Mongo URI is configured — make sure that database is reachable before starting.

I already validated that `mvn compile` builds cleanly with no errors, so the codebase itself is in a runnable state — you just need the external services (Mongo, optionally Redis/mail catcher) available per the `.env` configuration above.
